# core(Go 규칙) 시행착오

## 2026-10-15 — 맥(APFS)에서는 "같은 이름이 이미 있음"을 재현할 수 없었다
- **하려던 것:** NFD 이름과 NFC 이름 파일이 한 폴더에 있으면 바꾸지 않고 건너뛰는지 확인(`TestExistingTargetIsSkipped`).
- **증상:** NFD로 `보고서.txt`를 만든 뒤 NFC로 같은 이름을 쓰면 새 파일이 생기지 않고 **같은 파일을 덮어썼다**. 폴더에는 파일이 하나뿐이었다.
- **원인:** APFS는 이름을 저장할 때 모양은 보존하지만(NFD로 저장), 찾을 때는 정규화를 무시해 NFD/NFC를 같은 이름으로 본다. 윈도우 NTFS는 둘을 다른 이름으로 본다 — 그래서 윈도우에서 같은 폴더에 두 파일이 생길 수 있다.
- **해결:** 맥에서 파일이 하나만 생기면 `t.Skip("APFS는 NFD/NFC 이름을 같은 파일로 본다 — 윈도우 CI에서 확인")`. 이 테스트의 진짜 확인은 윈도우 러너(CI)에서 한다.
- **걸린 시간:** 5분
- **글감:** 예 — 맥에서는 절대 안 보이는 버그(연재 3편 "APFS와 NTFS의 한글 이름 차이").

## 2026-10-15 — 되돌리기 CSV의 "현재 경로"가 실제로 없는 경로였다
- **하려던 것:** 고친 뒤 원래 이름으로 돌릴 수 있게 `현재 경로,원래 이름` CSV 남기기.
- **증상:** `사진(NFD)/보고서.txt(NFD)`를 고치면 CSV에 `…/사진(NFD)/보고서.txt`가 적혔다. 파일은 그 뒤 폴더 이름이 바뀌어 `…/사진(NFC)/보고서.txt`에 있다.
- **원인:** 자식 → 부모 순서로 바꾸는데, 자식의 경로를 부모가 바뀌기 **전에** 적었다. 맥에서는 정규화를 무시하고 찾기 때문에 `os.Stat`이 성공해 버려 경로 검사만으로는 드러나지 않았다.
- **해결:** 모두 바꾼 뒤 각 경로의 상위 폴더 중 바뀐 것을 새 이름으로 고쳐 쓴다(`currentPath`). 테스트는 경로가 있는지에 더해 "풀어진 글자가 남지 않았는지"(NFC인지)도 본다 — 맥에서도 실패가 보이게.
- **걸린 시간:** 15분
- **글감:** 예 — 순서가 있는 일괄 작업에서 "기록 시점"이 틀리는 흔한 버그.

## 2026-10-15 — BOM을 글자로 넣었더니 go vet가 막았다
- **증상:** `vet: ./fix.go:67:19: illegal byte order mark`
- **원인:** 엑셀용 BOM을 문자열에 보이지 않는 글자(U+FEFF) 그대로 넣었다. Go 소스 중간의 BOM은 허용되지 않는다.
- **해결:** `f.Write([]byte{0xEF, 0xBB, 0xBF})`처럼 바이트로 쓴다.
- **걸린 시간:** 2분
- **글감:** 아니오 — 짧은 팁.

## 2026-10-16 — 윈도우 CI에서 "같은 이름 건너뛰기"를 처음 확인했다
- **하려던 것:** 맥에서 건너뛴 `TestExistingTargetIsSkipped`를 윈도우에서 실제로 돌리기.
- **결과:** GitHub Actions `windows-latest`에서 4개 테스트가 모두 통과했다(맥 러너는 같은 테스트를 건너뜀). NTFS는 NFD·NFC 이름을 다른 파일로 두어, 같은 폴더에 두 파일이 생기고 고칠 때 건너뛰는 것까지 확인됐다.
- **글감:** 예 — 연재 3편 "APFS와 NTFS의 한글 이름 차이"의 핵심 증거.
