# 윈도우 프로그램(Wails) 시행착오

## 2026-10-16 — 화면 폴더를 ../web으로 둘 수 없었다
- **하려던 것:** 브라우저 버전 화면(`web/`)을 윈도우 프로그램에서 그대로 쓰기(계획: `frontend:dir`을 `../web`으로).
- **원인:** Wails는 화면 파일을 `//go:embed all:frontend/dist`로 실행 파일에 넣는데, Go embed는 상위 폴더(`..`)를 가리킬 수 없다.
- **해결:** 빌드할 때 `frontend/copy-web.mjs`가 `web/`의 html·js를 `frontend/dist`로 복사한다(`wails.json`의 `frontend:build`). npm 의존성은 없앴다. 화면 코드는 여전히 한 벌이다.
- **걸린 시간:** 10분
- **글감:** 예 — 웹 화면을 데스크톱 앱에 재사용할 때의 함정.

## 2026-10-16 — 회사 윈도우 PC에서 처음 실행한 사용자의 피드백 10가지
- **확인된 것:** 다운로드 폴더의 PDF 2개(맥에서 받은 풀어진 이름)가 실제로 고쳐졌다. 핵심 기능은 됐다.
- **화면이 웹 그대로라 창에 맞지 않았다:** 웹 글자 크기(16px)·여백을 그대로 쓰니 시작 화면이 휑하고 큼직했다. 앱 안에서만 `body.app`으로 글자 약 2/3, 버튼 높이 3/4(세로 padding 0, 32px), 모서리 5px로 줄였다. 시작 창은 720×380으로 작게 띄우고 결과 표가 나올 때만 창을 키운다. 줄일 때 레이아웃이 무너지는 문제는 "작은 화면용 배치"를 따로 만드는 대신 **최소 크기(600×360)**를 두는 쪽으로 정했다 — 버튼 두 개짜리 화면에 반응형을 하나 더 얹는 건 과하다.
- **문구가 웹 기준이었다:** "모든 처리를 브라우저 안에서 합니다"는 프로그램에선 틀린 말이다. 앱에서는 "파일 내용에 접근하지 않으며 외부로 전송하지 않습니다"로 바꿨다.
- **"되돌리기 목록"은 아무도 이해하지 못했다:** 만든 쪽은 "이걸로 되돌릴 수 있다"는 뜻이었지만, 쓰는 사람에게는 그냥 "무엇을 고쳤는지 적힌 목록"이다. 이름을 `수정목록_날짜.csv`로 바꾸고, 기본은 만들지 않으며 체크박스를 켰을 때만 만든다. 체크 상태는 `%AppData%\hangul-name-fixer\settings.json`에 기억한다. 다 고친 뒤에는 CSV 경로와 📂 버튼(탐색기에서 그 파일 선택)을 보여 준다.
- **"건너뜀"보다 "(1) 붙이기":** 같은 이름이 있으면 건너뛰던 규칙을, 윈도우 탐색기처럼 `이름 (1).확장자`, 그다음 `(2)`로 바꿨다. 이미 `(1)`로 끝나면 `(1) (1)`로 잇지 않고 `(2)`로 올린다. Go(`core.UniqueName`)와 JS(`uniqueName`)에 같은 사례 6개로 테스트를 두었다.
- **폴더만 고를 수 있어 불편했다:** "파일 선택"(여러 개)을 더했다(`core.PlanFiles`, `FixFiles`).
- **확인 방법:** 앱 화면은 여전히 직접 누를 수 없어, 가짜 `window.go`·`runtime.WindowGetSize/SetSize`를 넣은 브라우저에서 시작 → 폴더 선택 → 수정 → 📂 → 체크 해제 저장 → 처음으로(창 크기 복귀) → 파일 선택(수정할 파일 없음)을 720×349·600×329, 라이트·다크로 확인했다(캡처: `img/2026-10-16_feedback_start.png`, `img/2026-10-16_feedback_done.png`). (1) 붙이기의 실제 파일 시험은 NFD·NFC가 같은 파일인 맥에서는 안 되므로 윈도우 CI에서 돈다.
- **걸린 시간:** 피드백 받고 반영까지 약 1시간
- **글감:** 예 — "만든 사람 말"과 "쓰는 사람 말"이 다르다(되돌리기 목록 → 수정 목록). 연재의 실사용 피드백 편 재료.

## 2026-10-16 — 두 번째 실행 피드백: 숨긴 줄이 보였고, 폴더 창에는 파일이 안 보였다
- **버그 — 숨긴 "원본 이름 저장 경로" 줄이 수정 전부터 보였다:** `hidden` 속성으로 숨겼는데 CSS에서 `.csv-line { display: flex }`를 줬다. 작성자 CSS의 `display`가 브라우저 기본 `[hidden] { display: none }`을 이긴다. 가짜 `window.go` 시험은 "수정 후 보이는지"만 봤지 "수정 전 숨는지"는 보지 않아 놓쳤다. `.csv-line[hidden] { display: none }`을 더하고 시험에 "수정 전에는 숨긴다"를 넣었다. 줄 위치도 표 아래·버튼 위로 옮겼다(요약 바로 아래에 표).
- **폴더 선택 창에 파일이 안 보여 당황스럽다:** 윈도우 폴더 선택 창은 폴더만 보여 주는 OS 창이라 바꿀 수 없다. 대신 창 제목에 "안의 파일은 선택한 뒤 목록에 표시됩니다"를 적고, **창에 끌어다 놓기**를 더했다(Wails `DragAndDrop.EnableFileDrop` + `runtime.OnFileDrop` — 전체 경로가 온다). 끌어 오는 동안 "여기에 놓으면…" 안내를 띄운다.
- **끌어다 놓기는 폴더도 섞여 온다:** 파일 선택용 `PlanFiles`를 `PlanPaths`로 넓혔다 — 파일은 그 이름만, 폴더는 안쪽(자식 먼저)과 폴더 자신의 이름까지, 겹치면 한 번만. 여러 폴더에서 온 항목이면 수정 목록 CSV는 **첫 번째 항목이 있는 폴더**에 남긴다(그 폴더는 이름이 바뀌지 않아 CSV 경로가 틀어지지 않는다).
- **문구·모양:** 안내 문구 "파일 내용에 접근하지 않으며, 데이터를 외부로 전송하지 않습니다. — 로컬 환경에서 파일명만 수정합니다.", 표 머리글 As is / To be / Status, As is 칸 글자 −2px, 버튼 줄 왼쪽 여백 5px.
- **글감:** 예 — "숨겼는데 보인다"(`hidden` vs `display`)는 흔한 함정. 시험이 '보여야 할 때'만 보고 '숨어야 할 때'를 안 봤다.

## 2026-10-16 — 의견 보내기: 로그인 없이, 구글 설문지로
- **조건(사용자):** GitHub 이슈처럼 어디 로그인하는 방식은 절대 안 된다. 간편해야 한다.
- **고른 것:** 앱 안 대화상자 → 구글 설문지 `formResponse`로 바로 전송 → 연결된 구글 시트에 쌓임. 메일 전달 서비스(가입·키 필요)와 mailto(회사 PC면 Outlook이 열림)보다 간단하다.
- **Go가 아니라 화면에서 보낸다:** Go `http.Client`로 보내면 성공 응답(200)을 확인할 수 있지만, Go는 윈도우 시스템 프록시 설정을 읽지 않아 회사망에서 막힐 수 있다. 화면(WebView2)의 `fetch`는 시스템 프록시를 따른다. 대신 구글은 다른 사이트의 요청에 응답을 보여 주지 않아(`no-cors`) "네트워크 오류가 없었다"까지만 안다 — 칸 번호를 시험으로 고정해 두어 그 위험을 줄였다.
- **칸 번호는 '미리 채워진 링크'에서 꺼낸다:** 칸마다 내용·연락처·버전·환경이라고 적어 만든 링크 하나만 `web/feedback.js`의 `FEEDBACK_LINK`에 넣으면 보낼 주소(`/formResponse`)와 `entry.N`을 코드가 찾는다(시험 4개).
- **함께 보내는 정보:** 앱 버전(빌드 때 `-ldflags -X main.version=…`, 시험판은 `test-실행번호`)과 윈도우 버전(`RtlGetVersion` — 윈도우 11도 10.0이라 빌드 번호까지). 파일 이름·내용은 보내지 않는다고 창에 적었다.
- **하마터면:** 시험용 가짜 `window.go`에 새 함수 `GetInfo`가 없자 `goApp().GetInfo()`가 동기적으로 터져 화면 전체가 멈췄다. 실제 앱에선 문제없지만, 부가 기능 하나가 화면 전체를 멈추면 안 되므로 `Promise.resolve().then(...)`으로 감쌌다.
- **남은 일:** 사용자가 설문지를 만들고 미리 채워진 링크를 주면 연결. 그 전까지 공개 웹 버전에서는 링크를 숨긴다.
