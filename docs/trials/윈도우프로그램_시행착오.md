# 윈도우 프로그램(Wails) 시행착오

## 2026-10-16 — 화면 폴더를 ../web으로 둘 수 없었다
- **하려던 것:** 브라우저 버전 화면(`web/`)을 윈도우 프로그램에서 그대로 쓰기(계획: `frontend:dir`을 `../web`으로).
- **원인:** Wails는 화면 파일을 `//go:embed all:frontend/dist`로 실행 파일에 넣는데, Go embed는 상위 폴더(`..`)를 가리킬 수 없다.
- **해결:** 빌드할 때 `frontend/copy-web.mjs`가 `web/`의 html·js를 `frontend/dist`로 복사한다(`wails.json`의 `frontend:build`). npm 의존성은 없앴다. 화면 코드는 여전히 한 벌이다.
- **걸린 시간:** 10분
- **글감:** 예 — 웹 화면을 데스크톱 앱에 재사용할 때의 함정.

## 2026-10-16 — 맥에서 윈도우 exe를 바로 만들 수 있었다
- **확인:** `wails build -platform windows/amd64` → `PE32+ executable (GUI) x86-64, for MS Windows`, 11.8MB. 윈도우 빌드는 cgo가 필요 없어 맥에서 교차 빌드가 된다. 같은 빌드를 GitHub Actions의 윈도우 러너에서도 돌린다.
- **글감:** 예.

## 2026-10-16 — 앱 화면 제어 권한이 없어 화면 연결은 가짜 Go 함수로 확인했다
- **하려던 것:** 맥에서 빌드한 앱을 띄워 폴더를 고르고 이름을 고쳐 보기.
- **상황:** 화면 제어 권한 요청이 거절돼 직접 누를 수 없었다.
- **대신 한 것:** Go 쪽(`Preview`·`FixAll`·되돌리기 CSV)은 임시 폴더로 단위 테스트, 화면 쪽은 브라우저에서 `window.go`를 가짜로 넣어 폴더 고르기 → 미리보기 → 모두 고치기 → 상태 표시까지 확인(캡처: `img/2026-10-16_desktop_ui.png`).
- **남은 확인:** 실제 윈도우 PC에서 exe를 실행해 탐색기의 풀어진 이름이 고쳐지는지(Task 7, 사용자).
- **글감:** 예 — "누를 수 없을 때" 무엇으로 대신 확인하는가.

## 2026-10-16 — [유머] 기여자 목록에 Claude가 당당하게 올라 있었다
- **발견:** 저장소를 공개하고 보니 GitHub 오른쪽 Contributors에 **claude**와 **jwkim1421** 두 명이 나란히 떠 있었다.
- **사용자 반응:** "당당하게 기여자에 claude라 jwkim1421 있는 거 귀엽네. 너가 너를 넣은 것도, 딱히 한 것도 없는 내 이름이 있는 것도 넘 웃김 ㅋㅋㅋ"
- **원인:** 커밋은 사용자의 git 계정(jwkim1421)으로 만들어졌고, 커밋 메시지 끝에 `Co-Authored-By: Claude <noreply@anthropic.com>`를 붙였다. GitHub는 이 줄을 보고 공동 작성자도 기여자로 센다. 그래서 코드를 쓴 쪽과 이름이 걸린 쪽이 둘 다 올라갔다.
- **해결:** 고치지 않는다. 사실 그대로다 — 한 명은 코드를 썼고, 한 명은 "만들자"고 했다. 둘 다 없었으면 이 도구도 없었다.
- **글감:** 예 — 연재 2편(Claude Code로 만들기)의 마무리 한 줄로.
