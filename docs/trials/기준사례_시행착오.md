# 기준사례 시행착오

## 2026-10-15 — 계획서의 예시 글자를 그대로 복사하면 테스트가 아무것도 검증하지 못한다
- **하려던 것:** 고치기 규칙의 기준 사례(`testdata/cases.json`)에 "NFD 입력 → NFC 기대값"을 적기.
- **증상:** 계획서에 적힌 `"input": "보고서.docx", "expected": "보고서.docx"`는 눈으로는 똑같다. 두 값이 실제로 다른 바이트인지(NFD/NFC) 화면에서 구분할 방법이 없다. 편집기·복사 과정에서 NFD가 NFC로 바뀌면 `changed: true` 사례가 사실은 이미 정상인 이름이 된다.
- **원인:** 유니코드 정규화는 보이는 모양이 같다. 맥의 일부 편집기와 입력기는 붙여 넣을 때 NFC로 합친다.
- **해결:** 사례 파일을 손으로 쓰지 않고 Python `unicodedata.normalize("NFD", …)`로 만들어 `\u` 이스케이프(`보…`)로 저장했다. 만들 때 `input != expected`가 `changed`와 일치하는지 검사한다.
- **걸린 시간:** 10분
- **캡처:** 없음
- **글감:** 예 — "눈으로 같은 두 문자열"을 테스트에 넣는 법은 이 도구의 핵심 함정이다.

## 2026-10-15 — 맥에 Go가 없었다
- **하려던 것:** core(Go) 테스트 실행.
- **증상:** `zsh: command not found: go`
- **해결:** `brew install go` → go1.27.2. 계획서는 Go 1.23 기준이라 `go.mod`는 `go 1.23`으로 두어 더 낮은 버전에서도 빌드되게 했다.
- **걸린 시간:** 3분
- **글감:** 아니오 — 환경 준비.
