# 브라우저 버전 시행착오

## 2026-10-15 — 맥 화면에서는 "지금 이름"과 "고친 이름"이 똑같아 보였다
- **하려던 것:** 고치기 전에 바뀔 이름을 미리 보여 주기.
- **증상:** 미리보기 표의 두 열이 맥에서 글자 하나 다르지 않게 보였다(`테스트/사진/보고서.txt` → `테스트/사진/보고서.txt`). 무엇이 고쳐지는지 사용자가 알 수 없다.
- **원인:** 맥은 풀어진 자모(NFD)도 합쳐서 그린다. 윈도우 탐색기만 낱자로 보여 준다.
- **해결:** 미리보기의 "지금 이름"을 윈도우에서 보이는 모양으로 바꿔 보여 준다(`asSeenOnWindows` — 조합용 자모 U+1100~를 낱자 ㄱ·ㅏ로). `ㅌㅔㅅㅡㅌㅡ/ㅅㅏㅈㅣㄴ/ㅂㅗㄱㅗㅅㅓ.txt` → `테스트/사진/보고서.txt`.
- **걸린 시간:** 10분
- **캡처:** docs/trials/img/2026-10-15_web_done.png
- **글감:** 예 — "같아 보이는 두 이름"을 화면에서 구별시키는 방법.

## 2026-10-15 — ZIP 안에서 고친 이름이 정상 이름과 겹치면 하나가 덮어써질 뻔했다
- **하려던 것:** 고친 이름으로 새 ZIP 만들기.
- **증상:** 한 ZIP에 `보고서.txt`(NFD)와 `보고서.txt`(NFC)가 같이 있으면, 고친 이름이 같은 경로가 되어 나중 것이 먼저 것을 덮어쓴다(처음 코드를 읽다 발견, 실행 전 수정).
- **해결:** 이미 정상인 이름을 먼저 넣어 자리를 잡고, 고친 이름이 겹치면 원래 이름 그대로 두고 "같은 이름이 있어 건너뜀"으로 표시한다.
- **확인 방법:** Python으로 두 이름을 모두 넣은 `collision.zip`을 만들어 브라우저 버전(헤드리스 Chromium)에 넣음 → 받은 ZIP에 두 파일이 내용 그대로 남음.
- **걸린 시간:** 10분
- **글감:** 예 — 이름 정규화 도구의 핵심 위험(충돌)을 ZIP에서도 지키기.

## 2026-10-15 — 맥에서 ditto로 만든 ZIP 확인
- **확인 방법:** NFD 이름의 폴더(`테스트/사진/보고서.txt`, `테스트/회의록 (1).txt`, `테스트/report.pdf`)를 `ditto -c -k --sequesterRsrc --keepParent`로 압축 → 브라우저 버전에 넣고 "모두 고치기" → 받은 ZIP의 이름 5개가 모두 NFC, 내용 그대로.
- **남은 확인:** "폴더 바로 고치기"(Chrome·Edge의 폴더 선택 창)는 사람이 폴더를 골라야 해서 자동 시험을 못 했다. `FileSystemHandle.move`가 사용자 폴더에서 동작하는지 Chrome·Edge에서 직접 확인이 필요하다.
- **글감:** 예 — 연재 2편 재료.
